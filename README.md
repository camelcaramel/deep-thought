# Deep Thought

**생각해야 풀리는 실무 문제**

회사에서 일하는 것처럼 **티켓을 받아 코드를 고치고, 운영에 배포하고, 그 결과에 대응하는 과정**을 내 PC에서 해 보는 실무 문제 시뮬레이터입니다.
평소 쓰는 AI 코딩 도구를 마음껏 써도 됩니다. 정답을 맞혔는지보다 **어떤 근거로 무엇을 판단했는지**를 봅니다.

이 문서는 **테스터(학생)용 사용 설명서**입니다. 처음부터 순서대로 따라 하면 됩니다.

> **사이트**: https://camelcaramel.github.io/deep-thought/ · **내려받기**: [최신 릴리스](https://github.com/camelcaramel/deep-thought/releases/latest) · **보고서 양식**: [docs/report-template.md](docs/report-template.md)
>
> **문의**: Discord 사용자명 `donghwik`

문제는 한 줄짜리 수정부터 Java 파일이 1,000개가 넘는 서비스 수정까지 있습니다.

어디서 찾든 이름은 **Deep Thought**입니다. 시작 메뉴, Windows의 설치된 앱 목록, macOS 응용 프로그램 폴더, Ubuntu 앱 목록 모두 같습니다.

## 1. 한눈에 보기

```
설치 ─▶ 준비 (문제 고르기 → 코드 폴더 → 시작)
          │
          ▼
   ① 티켓 ─▶ ② 수정 (AI 도구 사용 가능) ─▶ ③ 로컬 확인 (몇 번이든)
                      │                              │
                      │                              ▼
                      │                     ④ 운영 배포 (단계마다 한 번)
                      │                              │
                      │              ┌──── 결과 ─────┴──────┐
                      │              ▼                      ▼
                      │          문제 없음            ⑤ 운영 장애
                      │              │            로그 · 질문으로 원인 찾기
                      │              │                      │
                      │              │                      ▼
                      │              │            ⑥ 복구 배포 (한 번)
                      ▼              ▼                      ▼
      수정하지 않고 답하기 ─▶  ⑦ 기록 내려받기 · 보고서 · 짧은 인터뷰
```

- 문제 하나에 **수업 2시간 정도**가 걸립니다. 보고서는 3일 안에 냅니다.
- 이 프로그램의 "운영"은 진짜 서버가 아니라 내 PC에서 도는 가상 환경입니다. 마음 놓고 해 보되, **운영 배포 횟수는 정해져 있으니 신중하게** 누르세요.
- 프로그램 안의 시간은 빠르게 흐릅니다(실제 1초 = 가상 5분). 운영 배포 한 번은 실제로 5분쯤 걸립니다.

정해진 말:

| 말 | 뜻 |
| --- | --- |
| 티켓 | 내가 받은 일 |
| 코드 폴더 | 내가 고치는 코드가 있는 폴더 |
| 로컬 확인 | 고친 코드를 내 PC에서 띄워 보는 확인. 횟수 제한 없음 |
| 운영 배포 | 하루치 요청을 모두 보내 보는 배포. 단계마다 한 번 |
| 복구 배포 | 장애가 난 뒤의 운영 배포 |
| 질문 | Discord로 동료에게 묻는 것. 선생님이 동료 역할로 답합니다 |
| 기록 | 프로그램이 자동으로 적는, 내가 한 일 |

## 3. 설치

사전 안내 시간에 선생님과 함께 설치하는 것을 권합니다. 인터넷이 되는 곳에서 하세요.

### 받을 파일

**설치 파일은 153KB**(macOS 14KB, Ubuntu 13KB)이고, 나머지는 프로그램이 필요할 때 알아서 받습니다.

| PC | 받을 파일 | 크기 |
| --- | --- | --- |
| Windows 10·11 (64비트) | [`DeepThought-windows.exe`](https://github.com/camelcaramel/deep-thought/releases/latest/download/DeepThought-windows.exe) | 153KB |
| macOS 11 이상 (Apple Silicon·Intel) | [`DeepThought-macos.zip`](https://github.com/camelcaramel/deep-thought/releases/latest/download/DeepThought-macos.zip) | 14KB |
| Ubuntu 22.04 이상 (64비트) | [`DeepThought-ubuntu.deb`](https://github.com/camelcaramel/deep-thought/releases/latest/download/DeepThought-ubuntu.deb) | 13KB |

나머지를 받는 때와 양은 이렇습니다. 한 번 받으면 그다음부터는 바뀐 것만 받습니다.

| 언제 | 무엇을 | 크기 |
| --- | --- | --- |
| 처음 켤 때 | 프로그램 본체 | 31.8MB |
| 처음 켤 때, PC에 JDK 21이 없으면 | Java 실행 환경 | 약 200MB |
| 첫 문제를 준비할 때 | 빌드 도구(Gradle)와 라이브러리 | 약 210MB |

링크는 늘 최신판입니다. 받은 파일이 손상되지 않았는지 확인하려면 [릴리스 페이지](https://github.com/camelcaramel/deep-thought/releases/latest)에 적힌 SHA-256 값과 비교하세요.

코드 서명이 없는 실험용 프로그램이라 처음 열 때 Windows SmartScreen이나 macOS Gatekeeper의 경고가 뜰 수 있습니다. 아래 순서대로 여세요.

### Windows

1. `DeepThought-windows.exe`를 내려받으세요. 브라우저가 막으면 내려받기 목록에서 **유지**를 고르세요.
2. 받은 파일을 두 번 눌러 실행하세요.
3. "Windows의 PC 보호" 창이 나오면 **추가 정보 → 실행**을 누르세요.
4. 내려받을 크기를 확인하고 **설치하고 시작**을 누르세요. 사용자 폴더에 설치하므로 관리자 권한은 필요하지 않습니다. 다 받으면 창이 열립니다.
5. 다음부터는 시작 메뉴의 **Deep Thought**로 여세요. 받은 설치 파일은 지워도 됩니다.

### macOS

1. `DeepThought-macos.zip`을 내려받아 압축을 푸세요. Safari로 받으면 저절로 풀립니다.
2. **Deep Thought** 앱을 **응용 프로그램** 폴더로 옮기고 두 번 눌러 여세요.
3. 열 수 없다는 경고가 나오면 **완료**(또는 **취소**)를 누르세요. 휴지통으로 옮기지 마세요.
4. **시스템 설정 → 개인정보 보호 및 보안**을 열고 아래쪽 Deep Thought 옆의 **그래도 열기**를 누르세요. 다시 묻는 창에서도 여세요. macOS 14 이하는 앱을 **오른쪽 클릭 → 열기 → 열기**로도 됩니다.
5. 내려받을 크기를 확인하고 **설치하고 시작**을 누르세요. 받는 동안에는 알림으로 진행을 알려 주고, 다 받으면 창이 열립니다.
6. 다음부터는 응용 프로그램 폴더의 **Deep Thought**로 여세요.

### Ubuntu

1. `DeepThought-ubuntu.deb`를 내려받으세요.
2. 터미널에서 받은 폴더로 가세요: `cd ~/다운로드` (영어 환경은 `cd ~/Downloads`)
3. 설치하세요: `sudo apt install ./DeepThought-ubuntu.deb`
4. 앱 목록에서 **Deep Thought**를 여세요. 터미널에서는 `deep-thought`입니다.
5. 내려받을 크기를 확인하고 **설치하고 시작**을 누르세요. 다 받으면 창이 열립니다.

### 켜지면

- 주소창 없는 창이 열립니다. Edge나 Chrome이 없으면 기본 브라우저로 열립니다.
- 창이 안 열리면 브라우저에서 **http://127.0.0.1:17300/** 을 여세요.
- 아이콘을 한 번 더 누르면 프로그램이 새로 뜨지 않고 창만 다시 열립니다.
- 창을 모두 닫고 15분이 지나면 프로그램이 저절로 꺼집니다. 운영 배포가 도는 중에는 꺼지지 않습니다. 다시 켜도 진행 상황은 그대로입니다.
- 내려받다가 끊기면 다시 켜세요. 받던 데서 이어서 받습니다. 필요한 파일을 모두 받은 뒤에는 인터넷이 없어도 켜집니다.

### 예전 판을 쓰던 PC

0.2판이나 0.3.0판을 쓰던 PC는 예전 프로그램을 제거하고 새로 설치하세요. 예전 판의 기록은 새 판으로 옮겨지지 않습니다. 풀던 문제가 남아 있으면 제출할 파일을 먼저 받아 두고 선생님에게 물어보세요.

- **0.2판**: 풀어 둔 압축판 폴더를 지우세요.
- **0.3.0판, Windows**: 설정 → 앱 → 설치된 앱에서 **Deep Thought (IncidentSim)** 을 제거하세요.
- **0.3.0판, macOS**: 터미널에서 `/Applications/IncidentSim.app/Contents/MacOS/IncidentSim --uninstall`을 실행하고, 응용 프로그램 폴더의 **IncidentSim**을 휴지통에 넣으세요.
- **0.3.0판, Ubuntu**: `incident-sim --uninstall`을 실행하고, `sudo apt remove incident-sim`을 실행하세요.

예전 판의 기록과 코드 폴더(사용자 폴더의 `.incident-sim`, `incident-sim-codebase`)까지 지우려면 제거하기 전에 예전 프로그램의 **데이터 모두 지우기**를 누르세요.

## 4. 처음 실행: 준비 화면

처음 켜면 준비 화면이 차례로 나옵니다.

| 순서 | 화면 | 할 일 |
| --- | --- | --- |
| 01 | 문제 고르기 | 선생님이 알려 준 문제를 고르세요 |
| 02 | 코드 폴더 | 코드를 둘 폴더를 정하고 **이 폴더에 받고 점검하기**를 누르세요. 기본값을 그대로 써도 됩니다. **비어 있거나 아직 없는 폴더**여야 합니다. 소스와 Git 기록을 풀고 점검까지 이어서 합니다. 첫 문제에서는 빌드 도구와 라이브러리 약 210MB를 받느라 3~5분 걸릴 수 있습니다 |
| 03 | 시작 | "AI 도구에는 이 폴더만 여세요"라는 약속을 읽고 **알겠어요, 시작하기**를 누르세요 |

시작 화면에 나오는 코드 폴더 경로를 복사해 두세요. 앞으로 AI 코딩 도구와 편집기에서는 **이 코드 폴더만** 엽니다.

실패한 항목이 있으면 화면에 나오는 고치는 방법을 따르고 **점검 다시 실행**을 누르세요. 그래도 안 되면 [11장](#11-문제-해결과-자주-묻는-것)을 보거나 선생님을 부르세요.

## 5. 화면 안내

모든 화면이 같은 틀로 되어 있습니다.

| 자리 | 내용 |
| --- | --- |
| 머리줄 | 왼쪽에 **운영 상태**(운영 정상, 운영 배포 중, 운영 장애), 오른쪽에 도구: **티켓 · 로그 · 질문 · 기록** |
| 단계 줄 | 지금 어느 단계인지. 지금까지 드러난 단계만 보입니다 |
| 본문 | 지금 할 일 하나와 주 버튼 하나 |
| 옆 칸 | 중요한 숫자 하나, 코드 폴더(폴더 열기, 경로 복사), 최근 기록 |

**화면 색이 운영 상태입니다.** 정상이면 밝은 화면이고, 운영에 장애가 나면 화면 전체가 검게 바뀝니다. 주황은 잘못된 것에만 씁니다.

| 도구 | 하는 일 |
| --- | --- |
| **티켓** | 받은 일을 다시 읽습니다 |
| **로그** | 운영 로그를 검색합니다. 잠긴 로그는 **열람 요청**을 보내면 열립니다. 결과는 CSV로 받을 수 있습니다 |
| **질문** | 동료를 골라 질문을 적고 Discord로 보냅니다. 받은 답을 옮겨 적습니다 |
| **기록** | 내가 한 일이 시간순으로 적혀 있습니다. 과정 기록과 보고서 양식을 내려받습니다 |

코드 편집기 옆에 창을 좁게 두고 써도 됩니다.

## 6. 진행 순서

### ① 티켓

티켓을 읽습니다. 요청자, 우선순위, 바라는 것이 적혀 있습니다.
티켓을 처음 보고 무엇이 문제라고 생각했는지, AI 도구에 처음 무엇을 시켰는지가 보고서의 첫 항목이니 기억해 두세요.

### ② 수정

1. **코드 폴더**를 편집기와 AI 도구로 여세요.
2. 구조를 둘러보세요. 코드 폴더의 `README.md`에 실행 방법이 있습니다.
3. 코드를 고치세요. AI 도구에 무엇을 시켰고 어떤 답을 받았는지는 나중에 보고서에 쓰니 대화를 지우지 마세요.
4. 원하면 코드 폴더에서 직접 테스트를 돌려도 됩니다.
   - Windows: `gradlew.bat test`
   - macOS·Ubuntu: `./gradlew test`
5. Git 커밋은 해도 되고 안 해도 됩니다. 프로그램은 **폴더에 있는 지금 파일 그대로** 빌드합니다.

### ③ 로컬 확인: 몇 번이든

**로컬 확인 실행**을 누르면 프로그램이 내 코드를 빌드해 띄우고 요청을 보내 봅니다. 1분쯤 걸립니다.

- 결과는 **통과**, **실패 있음**, **빌드 실패** 같은 말과 요청 수로 나옵니다.
- 빌드가 실패하면 **빌드 출력 보기**로 오류를 확인하세요.
- 몇 번을 해도 기록에 남는 것 말고는 불이익이 없습니다.

### 수정하지 않고 답하기

고칠 것이 없다고 판단했다면 코드를 배포하지 않고 요청자에게 답을 보낼 수 있습니다. **모든 문제에 똑같이 있는 길**입니다.

- 수정 · 로컬 확인 화면에서 **수정하지 않고 답하기**로 들어갑니다. 요청자에게 보낼 답을 20자 이상 적으세요.
- 보내면 운영 배포 없이 보고서 단계로 넘어가고, **그 뒤에는 다시 고칠 수 없습니다.**

### ④ 운영 배포: 단계마다 한 번

1. **영향 분석 메모**를 20자 이상 적으세요. 이 수정이 누구에게 어떤 영향을 줄 수 있는지, 배포 전에 무엇을 확인했는지 적습니다.
2. 되돌릴 수 없다는 것을 확인하는 칸을 채우세요.
3. **운영 배포 시작**을 누르세요.

운영 배포에서는 하루치 요청이 들어옵니다. **실제로 5분쯤** 걸리고 시작하면 멈출 수 없습니다. 그동안 로그와 질문은 쓸 수 있습니다.

- 빌드 실패나 실행 실패로 끝나면 **횟수가 줄지 않습니다.** 고친 뒤 다시 하세요.
- 배포가 도는 동안 PC가 절전에 들어가면 결과를 믿을 수 없어 중단됩니다. 이때도 횟수는 그대로입니다. **배포 중에는 노트북 덮개를 닫지 마세요.**

### ⑤ 결과에 대응

- **문제가 없으면** 화면은 밝은 그대로이고 보고서 단계로 넘어갑니다. ⑦로 가세요.
- **장애가 나면** 화면이 검게 바뀌고 단계가 늘어납니다. 알림에는 겉으로 드러난 증상만 적혀 있습니다. 원인은 직접 찾으세요.

원인을 찾는 도구는 둘입니다.

**로그**
- 잠긴 로그는 **열람 요청**을 누르고 왜 보려는지 5자 이상 적으면 바로 열립니다. 이유는 기록에 남습니다.
- 검색어는 띄어쓰기로 여러 개를 넣으면 모두 들어간 줄만 찾습니다. 대소문자는 구분하지 않습니다.
- 한 번에 **500줄**까지 보입니다. 더 있으면 전체 줄 수가 나오니 검색어나 시간 범위를 좁히세요.
- **CSV 내려받기**는 지금 검색 조건 그대로 받습니다. 한 번에 **1만 줄까지** 담기고, 잠긴 로그는 열람 요청 뒤에만 담깁니다.
- 내려받은 일도 기록에 남습니다. 보고서에는 근거가 되는 줄만 골라 붙이세요.

**질문 (Discord)**
1. **질문**에서 누구에게 물을지 고르고 질문을 적으세요(5~500자).
2. 프로그램이 질문을 복사하고 Discord를 엽니다. `donghwik`과의 대화에 **직접 붙여 넣어 보내세요.** 프로그램이 저절로 보내는 것은 없습니다.
3. **선생님이 그 동료 역할로 답합니다.** 답이 오기까지 시간이 걸릴 수 있습니다.
4. 답을 받으면 질문 화면에서 **받은 답 옮겨 적기**로 그대로 남기세요. 질문과 답이 기록에 남습니다.

- 동료는 **자기 업무만** 압니다. 코드나 장애 원인을 대신 알려 주지 않습니다.
- 횟수 제한은 없습니다. 막연하게 묻기보다 구체적으로 물어야 쓸모 있는 답을 얻습니다.
- 중요한 내용은 다른 근거로도 확인하세요.

로그 줄이나 받은 답을 AI 도구에 붙여 넣고 같이 분석해도 됩니다.

### ⑥ 복구 배포: 한 번

원인을 찾아 코드를 고쳤으면 로컬 확인을 거쳐 **복구 배포 시작**을 누르세요. 방법은 ④와 같습니다(영향 분석 메모 필수).
복구 배포까지 끝나면 결과와 상관없이 보고서 단계로 넘어갑니다.

### ⑦ 기록과 보고서

**기록**에서
1. **과정 기록 내려받기**를 누르세요. 빌드, 로컬 확인, 로그 검색어, 열람 요청과 이유, 질문과 답, 배포와 메모가 시간순으로 담겨 있습니다.
2. **보고서 양식 내려받기**를 누르세요. 이 저장소의 [docs/report-template.md](docs/report-template.md)와 같습니다.
3. 다른 문제도 풀어야 하면, 파일을 모두 받은 뒤 다음 문제로 넘어가세요([11장](#11-문제-해결과-자주-묻는-것) 참고).

보고서는 6개 항목입니다: 처음 판단, 배포 전 확인, AI 활용, 배포 결과와 원인, 복구와 재발 방지, 돌아보기. A4 2~3장 분량으로 씁니다.
장애가 났더라도 과정을 솔직하고 구체적으로 돌아보면 좋은 보고서입니다. 근거를 쓸 때는 로그 줄, 받은 답, 실행 결과를 그대로 옮겨 적으세요.

## 7. 규칙과 제한

| 항목 | 제한 |
| --- | --- |

| 운영 배포 | 첫 배포 한 번, 장애가 나면 복구 배포 한 번 |

| 기록 | 내가 한 일은 모두 자동으로 남고, 골라 지울 수 없음 |

## 8. 테스터 약속

- **AI 도구에는 코드 폴더만 열어 줍니다.** 프로그램 폴더와 사용자 폴더의 `.deep-thought`는 AI 도구에 보여 주지 않습니다.
- 프로그램을 뜯어보거나(디컴파일), 기록을 지워 운영 배포를 다시 하지 않습니다.
- 실험이 끝날 때까지 다른 테스터에게 답이나 단서를 알려 주지 않습니다.
- AI와 나눈 대화는 지우지 않고 보고서에 붙입니다.

## 9. 제출물

문제마다 **3일 안에** 냅니다.

1. 문제 해결 보고서(기록 화면에서 받은 양식으로 작성)
2. 과정 기록 파일(`deep-thought-<문제>-<날짜>.md`)
3. AI 도구와 나눈 대화 기록(내보내기 파일이나 캡처)

제출한 뒤에 보고서를 바탕으로 10~15분 정도 짧은 인터뷰를 합니다.

## 10. 폴더와 제거

프로그램이 쓰는 폴더는 셋입니다.

| 폴더 | 들어 있는 것 | 위치 |
| --- | --- | --- |
| 코드 폴더 | 내가 고치는 코드 | 준비 화면에서 정한 곳. 기본값은 사용자 폴더의 `deep-thought-codebase` |
| 데이터 폴더 | 기록, 로그, 실행 결과, 첫 빌드 때 받은 라이브러리, 창 설정 | 사용자 폴더의 `.deep-thought` |
| 프로그램 폴더 | 프로그램 본체, 라이브러리, 필요하면 Java | 아래 표 |

| PC | 프로그램 폴더 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\DeepThought` |
| macOS | `~/Library/Application Support/DeepThought` |
| Ubuntu | `~/.local/share/deep-thought` |

프로그램은 코드 폴더 안에 파일을 만들지 않습니다. 빌드 결과물과 기록은 모두 데이터 폴더에만 생깁니다.

### 모두 지우기

1. 제출할 파일을 먼저 받아 두세요.
2. 프로그램의 **데이터 모두 지우기**를 누르세요. 지울 폴더를 확인하고 **모두 지우고 끄기**를 누르면 데이터 폴더와 (고르면) 코드 폴더를 지우고 프로그램이 꺼집니다. 되돌릴 수 없습니다. 실행이 도는 중에는 끝난 뒤에 지울 수 있습니다.
3. 프로그램을 제거하세요.
   - **Windows**: 설정 → 앱 → 설치된 앱에서 **Deep Thought**를 제거하세요.
   - **macOS**: 터미널에서 `"/Applications/Deep Thought.app/Contents/MacOS/DeepThought" --uninstall`을 실행하고, 앱을 휴지통에 넣으세요.
   - **Ubuntu**: `deep-thought --uninstall`을 실행하고, `sudo apt remove deep-thought`를 실행하세요.

프로그램만 제거하면 데이터 폴더와 코드 폴더는 남습니다.

## 11. 문제 해결과 자주 묻는 것

| 증상 | 해결 |
| --- | --- |
| 창이 안 열려요 | 브라우저에서 http://127.0.0.1:17300/ 을 여세요 |
| "Windows의 PC 보호", "열 수 없습니다" 경고 | [3장](#3-설치)의 방법으로 여세요 |
| Windows에서 "스마트 앱 컨트롤"이 막아요 | 그 PC에서는 실행할 수 없습니다. 설정을 바꾸지 말고 선생님에게 알리세요 |
| 처음 켤 때 내려받기가 실패해요 | 인터넷 연결(학교 Wi-Fi는 로그인)을 확인하고 다시 켜세요. 받던 데서 이어서 받습니다. 학교 프록시가 있으면 선생님에게 알리세요 |
| 첫 빌드가 실패해요 | 인터넷 연결을 확인하고 **점검 다시 실행**을 누르세요 |
| 코드 폴더가 비어 있지 않대요 | 다른 경로를 적거나, 그 폴더를 비운 뒤 다시 누르세요 |
| 로컬 확인에서 빌드 실패 | **빌드 출력 보기**로 컴파일 오류를 확인하고 코드를 고치세요 |
| 프로그램과 연결하지 못했대요 | 프로그램이 꺼진 것입니다. 아이콘을 다시 누르세요. 진행 상황은 남아 있습니다 |
| 운영 배포가 중단으로 끝났어요 | 절전이나 멈춤이 감지된 것입니다. 횟수는 그대로이니 PC가 잠들지 않게 하고 다시 하세요 |
| Discord가 안 열려요 | 질문은 이미 복사되어 있습니다. Discord를 직접 열고 `donghwik`에게 붙여 넣어 보내세요 |
| 포트가 사용 중이래요 | 그 포트를 쓰는 프로그램이나 직접 띄운 서비스를 끄고 다시 켜세요. 모르겠으면 PC를 다시 시작하세요 |

**Q. 코드 폴더의 서비스를 직접 띄워 봐도 되나요?**
네. 코드 폴더의 `README.md`에 실행 방법이 있습니다. 프로그램의 로컬 확인·운영 배포와는 별개입니다.

**Q. 가상 시각은 뭔가요?**
운영 배포에서 하루치 운영을 5분쯤으로 줄여 보여 주려고, 프로그램 안의 시계가 300배 빠르게 흐릅니다. 로그와 실행 화면의 시각은 이 가상 시각입니다.

**Q. 실수로 운영 배포를 눌렀어요.**
영향 분석 메모를 쓰고 확인 칸을 채운 뒤 시작 버튼을 눌러야만 시작됩니다. 그 전에는 취소할 수 있습니다.

**Q. 질문에는 누가 답하나요? AI인가요?**
선생님이 동료 역할로 답합니다. AI가 아닙니다.

**Q. 문제를 처음부터 다시 하고 싶어요.**
다시 할 수 없습니다. 꼭 필요하면 선생님에게 말하세요.

**Q. 한 문제를 다 풀었어요. 다음 문제는 어떻게 하나요?**
보고서 단계가 되면 다음 문제로 가는 길이 나옵니다. 창 안의 링크로 과정 기록과 로그 CSV를 먼저 받아 두고, 확인 칸을 채운 뒤 **지우고 다음 문제로**를 누르세요. 그 문제의 기록·로그·질문과 답·실행 결과와 (고르면) 코드 폴더가 지워지고 준비 화면으로 돌아갑니다. 마친 문제는 다시 고를 수 없습니다.
