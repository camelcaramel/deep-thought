# 실무형 장애 시뮬레이터 (실험판)

실제 회사에서 일하는 것처럼 **티켓을 받아 코드를 고치고, 운영 서버에 배포하고, 그 결과에 대응하는 과정**을 내 PC에서 체험하는 프로그램입니다.
평소 쓰는 AI 코딩 도구를 마음껏 써도 됩니다. 정답을 맞혔는지보다 **어떤 근거로 무엇을 판단했는지**를 봅니다.

이 문서는 **테스터(학생)용 사용 설명서**입니다. 처음부터 순서대로 따라 하면 됩니다.

> **내려받기**: [최신 릴리스](https://github.com/camelcaramel/incident-sim-tester/releases/latest) · 보고서 양식: [docs/report-template.md](docs/report-template.md)

## 1. 한눈에 보기

```
설치 ─▶ 환경 점검 (처음 한 번)
          │
          ▼
   ① 티켓 읽기 ─▶ ② 코드 수정 (AI 도구 사용 가능) ─▶ ③ 로컬 확인 (몇 번이든)
                                                          │
                                                          ▼
                                                 ④ 운영 배포 (단계마다 1번)
                                                          │
                                   ┌──────── 결과 ────────┴─────────┐
                                   ▼                                 ▼
                             문제 없음                       ⑤ 운영에서 문제 발생
                                   │                     로그 콘솔 · 담당자 채팅으로 원인 찾기
                                   │                                 │
                                   │                                 ▼
                                   │                        ⑥ 복구 배포 (1번)
                                   ▼                                 ▼
                         ⑦ 기록 내보내기 · 보고서 작성 · 짧은 인터뷰
```

- 시나리오 하나에 **수업 2시간 정도**가 걸립니다. 보고서는 3일 안에 냅니다.
- 이 프로그램 안의 "운영 서버"는 진짜 서버가 아니라 내 PC에서 도는 가상 환경입니다. 마음 놓고 해 보되, **운영 배포 횟수는 정해져 있으니 신중하게** 누르세요.
- 프로그램 안의 시간은 빠르게 흐릅니다 (실제 1초 = 가상 5분). 운영 배포 한 번이 가상으로 하루 남짓이고, 실제로는 5분 정도 걸립니다.

## 2. 준비물

| --- | --- |
| PC | Windows 10·11, macOS 또는 Ubuntu(64비트). RAM 8GB 이상 (16GB 권장), 디스크 여유 2GB |
| 인터넷 | 처음 빌드할 때 라이브러리를 내려받고, AI 담당자와 대화할 때 필요합니다 |

## 3. 설치

사전 안내 시간에 선생님과 함께 설치하는 것을 권합니다. 첫 빌드 때문에 인터넷이 되는 곳에서 하세요.

### 받을 파일

**선생님이 설치 파일을 따로 나눠 줬다면 그 파일을 쓰세요.** 아니면 [릴리스 페이지](https://github.com/camelcaramel/incident-sim-tester/releases/latest)에서 내 PC에 맞는 파일을 받습니다.

| PC | 받을 파일 | Java 설치 |
| --- | --- | --- |
| Windows 10·11 | `IncidentSim-0.2.2-windows-portable.zip` (압축만 풀면 실행) | 필요 없음 (안에 들어 있음) |
| Ubuntu (64비트) | `IncidentSim-0.2.2-linux-x64-portable.tar.gz` (압축을 풀고 터미널에서 실행) | 필요 없음 (안에 들어 있음) |
| macOS, 또는 위 파일이 안 될 때 | `incident-sim-fallback.zip` (예비용 묶음) | **JDK 21 이상 필요** |

받은 파일이 손상되지 않았는지 확인하고 싶으면 릴리스에 적힌 SHA-256 값과 비교하세요.

> **담당자 채팅 안내**: 릴리스 페이지의 공개 파일에는 AI 담당자 연결 정보가 들어 있지 않아서, 지금은 담당자 채팅을 쓸 수 없습니다. 관련 문의는 **디스코드 사용자명 `donghwik`** 으로 해 주세요. 선생님이 AI 담당자가 들어 있는 설치 파일을 따로 줬다면 그 파일을 쓰세요.

### Windows

선생님에게 받은 파일이 무엇인지에 따라 둘 중 하나를 따릅니다.

**설치 파일(`IncidentSim-0.2.2.msi`)을 받았다면**
1. `.msi`를 더블클릭합니다.
2. "Windows의 PC 보호" 파란 창이 뜨면 **추가 정보 → 실행**을 누릅니다. (서명하지 않은 실험용 프로그램이라 뜨는 경고입니다)
3. 설치 폴더는 기본값 그대로 두고 **다음 → 설치**를 누릅니다.
4. 시작 메뉴나 바탕 화면에 **IncidentSim**이 생깁니다.

**압축 파일(`IncidentSim-0.2.2-windows-portable.zip`)을 받았다면**
1. 압축을 원하는 곳에 풉니다. 예: `C:\IncidentSim`
   - 바탕 화면이나 OneDrive 폴더보다는 짧은 경로를 권합니다.
2. 풀린 폴더의 `IncidentSim\IncidentSim.exe`를 실행합니다.
3. 경고 창이 뜨면 **추가 정보 → 실행**을 누릅니다.

### macOS

macOS용 설치 파일(`.dmg`)은 아직 공개하지 않았습니다. 선생님이 `.dmg`를 줬다면:
1. `IncidentSim-0.2.2.dmg`를 엽니다.
2. `IncidentSim`을 **응용 프로그램** 폴더로 끌어다 놓습니다.
3. 처음 열 때 "확인되지 않은 개발자" 경고가 뜨면, 응용 프로그램 폴더에서 앱을 **오른쪽 클릭 → 열기 → 열기**를 누릅니다.

`.dmg`가 없으면 아래 **예비용 묶음**을 씁니다. 터미널에서 `java -version`을 쳐서 21 이상이 나오는지 먼저 확인하세요. 없으면 [Adoptium](https://adoptium.net/)에서 **JDK 21**을 설치합니다.

### Ubuntu (Linux)

64비트 PC(x64)용입니다. Java는 설치하지 않아도 됩니다.
1. 터미널을 열고 받은 폴더로 갑니다. 예: `cd ~/다운로드` (영어 환경은 `cd ~/Downloads`)
2. 압축을 풉니다: `tar xzf IncidentSim-0.2.2-linux-x64-portable.tar.gz`
   - 파일 관리자에서 "여기에 풀기"로 풀어도 됩니다.
3. 실행합니다: `./IncidentSim/bin/IncidentSim`
   - 파일 관리자에서 더블클릭하면 안 열릴 수 있으니 터미널에서 실행하세요.
   - **실행한 터미널 창을 닫으면 프로그램도 꺼집니다.** 다 쓸 때까지 열어 두세요.

Chrome이나 Edge(deb로 설치한 것)가 있으면 앱 창으로, 없으면 Firefox 같은 기본 브라우저로 열립니다.

### 예비용 묶음 (설치 파일이 안 될 때만)

`incident-sim-fallback.zip`을 쓰려면 이 PC에 **JDK 21 이상**이 있어야 합니다 (JRE가 아니라 JDK).
1. 압축을 풉니다.
2. Windows는 `run-launcher.bat`을 더블클릭, macOS·Linux는 터미널에서 `sh run-launcher.sh`를 실행합니다.

### 실행하면

- 몇 초 뒤 주소창 없는 창(앱 창)이 열립니다. Edge나 Chrome이 있으면 그것으로, 없으면 기본 브라우저로 열립니다.
- 창이 안 열리면 브라우저에서 **http://127.0.0.1:17300/** 을 직접 여세요.
- 아이콘을 한 번 더 누르면 프로그램이 새로 뜨지 않고 창만 다시 열립니다.
- 창을 모두 닫고 15분이 지나면 프로그램이 저절로 꺼집니다. 배포가 도는 중에는 꺼지지 않습니다. 다시 쓰려면 아이콘을 누르면 되고, 진행 상황은 그대로 남아 있습니다.

## 4. 처음 실행: 환경 점검

처음 실행하면 **환경 점검** 화면이 나옵니다. 위에서부터 차례로 진행하세요.

| 순서 | 항목 | 할 일 |
| --- | --- | --- |
| 01 | 시나리오 선택 | 선생님이 알려 준 시나리오를 고르고 **선택**을 누릅니다 |
| 02 | 코드베이스 받을 폴더 | 기본값(`사용자 폴더\incident-sim-codebase\<시나리오>`)을 그대로 써도 됩니다. 다른 곳에 두려면 경로를 직접 입력합니다. **비어 있거나 없는 폴더**여야 합니다. **코드베이스 풀기**를 누릅니다 |
| 03 | 코드베이스 풀기 | 폴더에 매점 서비스 소스와 Git 커밋 기록이 풀리면 완료됩니다 |
| 04 | 포트 확인 | 자동으로 확인합니다 |
| 05 | 첫 빌드 · 라이브러리 내려받기 | **점검 실행**을 누르면 시작합니다. 처음에는 3~5분 걸릴 수 있습니다 |
| 06 | AI 담당자 연결 확인 | 자동으로 확인합니다 |

모든 항목에 **완료**가 켜지면 **모두 준비**를 누릅니다. 마지막에 이런 안내가 나옵니다.

> **AI 도구에는 이 폴더만 여세요**
> `C:\Users\<이름>\incident-sim-codebase\<시나리오>`

이 경로를 복사해 두세요. 앞으로 AI 코딩 도구와 편집기에서는 **이 폴더만** 엽니다.

실패한 항목이 있으면 그 줄에 나오는 해결 방법을 따르고 **점검 다시 실행**을 누르세요. 그래도 안 되면 [10장](#10-문제-해결과-자주-묻는-질문)을 보거나 선생님을 부르세요.

## 5. 화면 안내

왼쪽 메뉴로 화면을 옮깁니다. 맨 위 띠에는 **현재 단계**, **남은 운영 배포 횟수**, **가상 시각**(실행 중일 때), **장애 알림**(있을 때)이 항상 보입니다.

| 메뉴 | 하는 일 |
| --- | --- |
| **01 상황실** | 티켓 내용, 진행 단계(티켓 확인 → 수정·로컬 확인 → 운영 배포 → 장애 대응 → 복구 배포 → 보고서), 지금 할 일 한 줄 안내, 장애 알림, 최근 활동 |
| **02 로그 콘솔** | 운영 로그 검색. 검색어, 시간 범위(가상 시각), 출처(로그 종류)를 고릅니다. 잠긴 출처는 **열람 요청**을 보내야 볼 수 있습니다. 검색 결과는 **CSV 내려받기**로 받을 수 있습니다 |
| **03 담당자 채팅** | 다른 부서 담당자(AI)에게 질문합니다. 담당자마다 남은 질문 수가 보입니다. 지금 배포판에서는 쓸 수 없고, 문의는 **디스코드 사용자명 `donghwik`** 으로 합니다 |
| **04 배포** | **로컬 확인**(무제한)과 **운영 배포**(단계마다 1번), 실행 진행 상황, 결과, 실행 기록 |
| **05 기록** | 내가 한 일이 시간순으로 자동 기록된 타임라인, **보고서 양식 내려받기**, **과정 기록 내보내기**, 시나리오가 끝나면 **다음 문제 풀기** |

## 6. 진행 순서

### ① 티켓 읽기 (상황실)

상황실의 티켓 카드를 읽습니다. 요청자, 우선순위, 대상 코드가 적혀 있습니다.
티켓을 처음 보고 무엇이 문제라고 생각했는지, AI 도구에 처음 무엇을 시켰는지가 보고서의 첫 항목이니 기억해 두세요.

### ② 코드 수정 (AI 코딩 도구)

1. 환경 점검에서 받은 **코드베이스 폴더**를 편집기와 AI 도구로 엽니다.
2. 매점 서비스(Spring Boot)의 구조를 둘러봅니다. `README.md`에 실행 방법과 API 목록이 있습니다.
3. 코드를 고칩니다. AI 도구에 무엇을 시켰고 어떤 답을 받았는지는 나중에 보고서에 쓰니 대화를 지우지 마세요.
4. 원하면 코드베이스에서 직접 테스트를 돌려도 됩니다.
   - Windows: `gradlew.bat test`
   - macOS·Ubuntu: `./gradlew test`
5. Git 커밋은 해도 되고 안 해도 됩니다. 런처는 **폴더에 있는 지금 파일 그대로** 빌드합니다.

### ③ 로컬 확인 (배포 화면) — 몇 번이든 가능

**로컬 확인 실행**을 누르면 런처가 내 코드를 빌드해 띄우고, 가상 점심시간 동안의 요청을 흘려 보내 봅니다. 1분 정도 걸립니다.

- 진행 단계: 빌드 → 실행 → 리플레이 → 판정
- 결과: 성공률, 보낸 요청, 실패 요청 수, 실패 예시
- 빌드가 실패하면 **빌드 출력 보기**로 오류를 확인하세요. 로컬 확인은 몇 번을 해도 기록 말고는 불이익이 없습니다.

### ④ 운영 배포 (배포 화면) — 단계마다 1번

준비가 됐으면 **운영 배포 시작**을 누릅니다.

1. 확인 창에 **영향 분석 메모**를 20자 이상 씁니다. 이 수정이 누구에게 어떤 영향을 줄 수 있는지, 배포 전에 무엇을 확인했는지 적습니다.
2. "운영 배포는 되돌릴 수 없고…" 확인란에 체크합니다.
3. **확인했어요, 배포 시작**을 누릅니다.

운영 배포는 가상으로 하루 남짓 동안 운영 요청과 밤사이 작업까지 모두 흘려 보냅니다. **실제로 5분쯤** 걸리고, 시작하면 멈출 수 없습니다. 그동안 로그 콘솔과 담당자 채팅은 쓸 수 있습니다.

- 빌드 실패나 서버 기동 실패로 끝나면 **배포 횟수가 줄지 않습니다.** 고친 뒤 다시 하세요.
- 운영 배포가 도는 동안 PC가 절전 모드에 들어가면 결과를 믿을 수 없어 중단됩니다. 이때도 배포 횟수는 그대로입니다. **배포 중에는 노트북 덮개를 닫지 마세요.**

### ⑤ 결과 확인과 장애 대응

운영 배포가 끝나면 상황실과 상단 띠에 결과가 나옵니다.

- **문제가 없으면** 단계가 "보고서"로 넘어갑니다. ⑦로 가세요.
- **문제가 생기면** 주황색 장애 알림(`INCIDENT ACTIVE`)이 뜨고 단계가 "장애 대응"으로 바뀝니다. 알림에는 겉으로 드러난 증상만 적혀 있습니다. 원인은 직접 찾아야 합니다.

원인을 찾는 데 쓰는 도구:

**로그 콘솔**
- 처음에는 **앱 서버 로그** 7일치만 열려 있습니다. 운영 배포를 하면 그 실행의 로그가 더해집니다.
- 잠긴 출처(🔒)는 **열람 요청**을 누르고 "왜 보려는지"를 5자 이상 적으면 바로 열립니다. 이유는 과정 기록에 남습니다.
- 검색어는 띄어쓰기로 여러 개를 넣으면 모두 들어간 줄만 찾습니다. 대소문자는 구분하지 않습니다.
- 한 번에 **500줄**까지 보입니다. 더 있으면 "전체 N줄"이 표시되니 검색어나 시간 범위를 좁히세요.
- 결과 표 위의 **CSV 내려받기**를 누르면 지금 검색 조건 그대로 CSV 파일을 받습니다. 한 번에 **1만 줄까지** 담기고, 엑셀에서 한글이 깨지지 않고 열립니다. 잠긴 출처는 열람 요청 뒤에만 담깁니다.
- 내려받은 일(조건과 줄 수)도 과정 기록에 남습니다. 보고서에는 근거가 되는 줄만 골라 붙이세요.

**담당자 채팅**
- 담당자는 **자기 업무만** 압니다. 서버 코드나 장애 원인을 대신 알려 주지 않습니다.
- 질문은 **담당자마다 5번, 한 번에 300자까지**입니다. 막연하게 묻기보다 구체적으로 물어야 쓸모 있는 답을 얻습니다.
- 답이 오기까지 시간이 조금 걸릴 수 있습니다. "답변 기다리는 중"이 보이면 기다리세요.
- 담당자의 말이 항상 맞는다는 보장은 없습니다. 사람처럼 잘못 기억하는 것도 있습니다. 중요한 내용은 로그 같은 다른 근거로 확인하세요.
- 지금 배포판에서는 **담당자 채팅을 쓸 수 없습니다.** 화면에 "지금은 담당자 채팅을 쓸 수 없어요"가 보이면, 관련 문의는 **디스코드 사용자명 `donghwik`** 으로 해 주세요.

AI 코딩 도구에 로그 줄이나 담당자 답변을 붙여 넣고 같이 분석해도 됩니다.

### ⑥ 복구 배포 — 1번

원인을 찾아 코드를 고쳤으면 로컬 확인을 거쳐 **복구 배포 시작**을 누릅니다. 방법은 ④와 같습니다 (영향 분석 메모 필수).
복구 배포까지 끝나면 결과와 상관없이 단계가 "보고서"로 넘어갑니다.

### ⑦ 기록 내보내기와 보고서

**기록** 화면에서
1. **과정 기록 내보내기 (.md)**: 빌드, 로컬 확인, 로그 검색어, 열람 요청과 이유, 담당자 질문과 답, 배포와 메모, 장애가 시간순으로 담긴 파일을 받습니다.
2. **보고서 양식 내려받기**: 보고서 틀(마크다운)을 받습니다.
3. 다른 시나리오도 풀어야 하면, 파일을 모두 받은 뒤 **다음 문제 풀기**로 넘어갑니다 ([10장 Q&A](#10-문제-해결과-자주-묻는-질문) 참고).

보고서 양식은 6개 항목입니다: 처음 판단, 배포 전 확인, AI 활용, 배포 결과와 원인, 복구와 재발 방지, 돌아보기. A4 2~3장 분량으로 씁니다.
장애가 났더라도 과정을 솔직하고 구체적으로 돌아보면 좋은 보고서입니다. 근거를 쓸 때는 로그 줄, 담당자 답변, 실행 결과를 그대로 옮겨 적으세요.

## 8. 테스터 약속

- **AI 도구에는 코드베이스 폴더만 열어 줍니다.** 런처 설치 폴더, 사용자 폴더의 `.incident-sim` 폴더는 AI 도구에 보여 주지 않습니다.
- 런처를 풀어 보거나(디컴파일), 기록을 지워 운영 배포를 다시 하지 않습니다.
- 실험이 끝날 때까지 다른 테스터에게 답이나 단서를 알려 주지 않습니다.
- AI와 나눈 대화는 지우지 말고 보고서에 첨부합니다.

약속을 어긴 것을 솔직하게 적어 내는 것은 감점하지 않습니다.

## 9. 제출물

시나리오마다 **3일 안에** 냅니다.

1. 문제 해결 보고서 (기록 화면에서 받은 양식으로 작성)
2. 과정 기록 파일 (`incident-sim-<시나리오>-<날짜>.md`)

제출 뒤에 보고서를 바탕으로 10~15분 정도 짧은 인터뷰를 합니다.

## 10. 문제 해결과 자주 묻는 질문

| 증상 | 해결 |
| --- | --- |
| 창이 안 열려요 | 브라우저에서 http://127.0.0.1:17300/ 을 엽니다 |
| "확인되지 않은 개발자", "PC 보호" 경고 | [3장](#3-설치)의 방법으로 실행합니다 |
| 첫 빌드가 실패해요 | 인터넷 연결을 확인하고 **점검 다시 실행**을 누릅니다. 회사·학교 프록시가 있으면 선생님에게 알리세요 |
| 코드베이스 풀기에서 "비어 있지 않은 폴더" | 다른 경로를 입력하거나, 그 폴더를 비운 뒤 다시 누릅니다 |
| 로컬 확인에서 빌드 실패 | **빌드 출력 보기**로 컴파일 오류를 확인하고 코드를 고칩니다 |
| "런처에 다시 연결하는 중"이 계속 보여요 | 프로그램이 꺼진 것입니다. 아이콘을 다시 누르세요. 진행 상황은 남아 있습니다 |
| 운영 배포가 "중단"으로 끝났어요 | 절전·멈춤이 감지된 것입니다. 배포 횟수는 그대로이니 PC가 잠들지 않게 하고 다시 하세요 |
| 담당자 채팅에 질문 칸이 없어요 | 지금은 담당자 채팅을 쓸 수 없는 상태입니다. 관련 문의는 디스코드 사용자명 `donghwik` 으로 해 주세요 |
| 포트가 사용 중이래요 | 다른 IncidentSim 창이나 직접 띄운 매점 서비스를 끄고 다시 실행합니다 |

**Q. 코드베이스에서 매점 서비스를 직접 띄워 봐도 되나요?**
네. 코드베이스 폴더에서 `gradlew.bat bootRun`(macOS·Ubuntu는 `./gradlew bootRun`)으로 띄우면 `http://localhost:8080`에서 동작합니다. 샘플 데이터가 들어 있는 로컬용 설정입니다. 런처의 로컬 확인·운영 배포와는 별개입니다.

**Q. 런처가 내 코드베이스 폴더에 파일을 만드나요?**
아니요. 빌드 결과물과 실행 기록은 모두 사용자 폴더의 `.incident-sim`에만 생깁니다.

**Q. 가상 시각은 뭔가요?**
운영 배포에서 하루치 운영을 5분 안에 보여 주려고, 프로그램 안의 시계가 300배 빠르게 흐릅니다. 로그와 화면의 시각은 모두 이 가상 시각입니다.

**Q. 실수로 운영 배포를 눌렀어요.**
확인 창에서 **취소**를 누르면 됩니다. 메모를 쓰고 체크한 뒤 **확인했어요, 배포 시작**을 눌러야만 시작됩니다.

**Q. 시나리오를 처음부터 다시 하고 싶어요.**
테스터는 다시 할 수 없습니다. 꼭 필요하면 선생님에게 말하세요.

**Q. 한 문제를 다 풀었어요. 다음 문제는 어떻게 하나요?**
운영 배포가 끝나 단계가 "보고서"가 되면 상황실과 기록 화면에 **다음 문제 풀기** 카드가 나옵니다. **이 문제 마치고 다음 문제로**를 누르고, 창 안의 단추로 과정 기록(.md)과 로그 CSV를 먼저 받아 둔 뒤 확인란에 체크하고 **지우고 다음 문제로**를 누릅니다. 그 문제의 기록·로그·담당자 대화·실행 결과와 (고르면) 코드베이스 폴더가 지워지고 환경 점검 화면으로 돌아갑니다. 거기서 다음 시나리오를 고르면 됩니다. 마친 문제는 목록에 "(마침)"으로 보이고 다시 고를 수 없습니다.

**Q. 이 PC에서 프로그램이 만든 데이터를 모두 지우고 싶어요.**
왼쪽 메뉴 맨 아래(또는 환경 점검 화면 맨 아래)의 **데이터 모두 지우기**를 누릅니다. 지울 폴더 목록을 확인하고 체크한 뒤 **모두 지우고 끄기**를 누르면, 사용자 폴더의 `.incident-sim`(기록, 로그, 실행 결과, 첫 빌드 때 내려받은 라이브러리, 앱 창 설정)과 코드베이스 폴더를 지우고 프로그램이 꺼집니다. 되돌릴 수 없으니 제출할 파일은 먼저 받아 두세요. 프로그램 자체는 Windows 설정 → 앱에서 IncidentSim을 제거하거나(설치 파일), 풀어 둔 폴더를 지우면(압축판) 됩니다. 로컬 확인·운영 배포가 도는 중에는 끝난 뒤에 지울 수 있습니다.
